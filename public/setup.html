01 · 接入 Supabase 实时数据库

  1. 在 Supabase 创建项目。在 SQL Editor 新建查询，完整运行下面提供的建表脚本。
  2. 在 Authentication → Users 添加 / 邀请自己的邮箱。作为个人应用，在 Auth 配置中关闭公众注册。
  3. 把 https://user-balance.github.io/diancai/ 配到 Site URL 和 Redirect URLs。
  4. 找到项目 URL 和 publishable key（旧项目可用 anon key），在点菜本 →「数据与设置」里填写并保存。
  5. 输入自己的注册邮箱，发送登录邮件；点击邮件里的链接回到点菜本。
  6. 首次云端菜谱可以为空，点击「将本地菜谱导入云端」。确认右上角显示「实时同步已连接」。
下载完整建表脚本

仅需两个公开配置。数据库密码、service_role、secret key 不应进入网页。本应用按登录用户隔离菜谱，并在数据库里限制重名。

默认邮件发送和免费项目可能有限制，请按 Dashboard 的提示配置 SMTP 或恢复项目。

接入后的验收

新增菜谱后检查数据库记录、刷新保留、两台设备实时更新、同时记录下厨不丢次数、另一用户无法访问、未登录不能读取私有数据。云端错误会显示提示，不会静默写到本地。

02 · GitHub 主页支持数据库吗？

GitHub Pages 托管静态网页，不托管可写的数据库服务器。菜谱的数据库放在 Supabase，网页通过 API 与 Realtime 订阅读写。仓库内的 JSON 或 SQLite 文件不等同于在线数据库。

点菜本使用独立仓库 User-Balance/diancai，页面在账号域名的 /diancai/ 路径发布。后续更新运行 npm run pages:prepare，提交并推送，等待 Pages build 成功，再验证线上网页。

03 · 后续发布微信小程序

当前是手机适配网页，可在微信内打开。正式原生小程序需要微信主体账号、AppID、开发者工具、后端权限和平台审核。

步骤具体工作
注册与资料申请个人小程序，设置名称和符合实际功能的开放类目，获取 AppID。
原生开发把列表、详情、编辑和点菜页面改为 WXML / WXSS；复用菜谱模型，重写存储适配。
数据与身份可选微信云开发；如共用 Supabase，则由符合域名要求的后端验证微信身份并映射用户。
备案与隐私完成小程序备案、隐私指引，配置实际使用的合法 HTTPS / WSS 服务域名。
上传与审核上传开发版、真机体验、提交审核；通过后由管理员发布，验收正式版本。

个人主体暂不支持 web-view，不默认把网页套壳发布。普通网络服务域名须满足微信的备案等规则，不能直接假定 github.io / supabase.co 合规可用。

04 · 发布到 OpenAI 提供的域名

OpenAI 现在提供 ChatGPT Sites，成功部署后返回生产 deployment URL，也支持符合条件的自有域名；具体默认域名以实际部署结果为准。请在本人已登录的 ChatGPT / Codex 里进入 Sites，无需提供账号密码或 API key。

  1. 使用 @Sites 或「website」描述启动工作流，提供本项目源码。
  2. 先让 Sites 检查兼容性并保存可审阅版本，优先保留 Supabase 数据层。
  3. 验证分类、编辑、去重、次数、评分、手机布局和实际数据保存。
  4. 选择仅自己 / 邀请访问 / 公开访问；实际选项取决于账号与工作区权限。
  5. 部署后获取真实生产部署链接，并把该地址加入 Supabase Redirect URLs。
使用 Sites 检查并准备发布这个个人点菜网页项目。先检查兼容性并保存可审阅版本。保留现有功能和 Supabase 数据层，按登录用户隔离菜谱。通过验收后按我选择的范围部署，返回真实 deployment URL。

Sites 也提供 D1 结构化存储与 R2 文件存储；迁移数据层需要额外实现与验证。保存站点版本不会自动保存用户菜谱。官方在核实日说明 Hosting 免费到 2026-12-31，计划从 2027-01-01 按超出套餐额度的使用量计费；上线前请再次核对。
