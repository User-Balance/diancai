现在可以在微信里打开网页地址试用。若希望通过微信搜索 / 小程序码进入，并使用正式小程序能力，需要下面的原生发布流程。

## 先选实现路径

| 路径 | 适合 | 工作和限制 |
| --- | --- | --- |
| 原生小程序 + 微信云开发 / 云托管 | 个人用、希望少配置自己的域名 | 将界面改为 WXML / WXSS；复用菜谱字段与去重逻辑，数据层改为云函数 / 数据库权限；若与网页共用数据，需要同步设计 |
| 原生小程序 + 已备案 API 后端 + 同一数据库 | 希望网页、小程序共享同一套菜谱 | 后端验证微信身份并映射到数据库用户；配置合法 HTTPS / WSS 域名、权限和跨端同步 |
| web-view 套当前网页 | 主体资格符合 web-view 开放范围 | 个人主体暂不支持 web-view；业务域名也有校验限制，因此不作为默认个人发布方案 |

本项目采用原生界面；未配置云环境时使用本地存储。配置云环境后，云函数验证 Supabase 登录 JWT，再按原有 RLS 访问网页共用的数据库。小程序通过下拉刷新和页面重新进入同步；网页使用 Realtime 订阅。

## 流程

1. **申请账号。** 在微信公众平台注册「小程序」，填写主体、管理员资料。本人完成实名、扫码确认和需接受的协议。
2. **完善资料。** 配置名称、头像、简介，选择后台当前开放且符合真实功能的个人主体类目；不要默认套用商家点餐 / 交易类目。
3. **取得 AppID。** 设置 → 开发设置获取 AppID，成员管理绑定开发者，安装官方微信开发者工具。
4. **开发和预览。** 建立菜谱列表、分类、详情、编辑、今日菜单、下厨记录、登录页；真机预览验证表单和数据库操作。
5. **配置数据服务。** 微信云开发可使用云函数 / 云托管；自建后端需配置已备案 HTTPS 域名和 WSS 域名。微信文档规定普通网络服务域名须经过 ICP 备案，不能直接假定 `supabase.co` / `github.io` 可以当作个人的合法后端域名。
6. **处理身份和权限。** 使用微信登录；由服务端验证身份，把稳定用户身份映射到菜谱 owner。不要把 Supabase service_role / 微信 AppSecret 放进客户端。若采用 CloudBase，也不能依赖隐藏按钮保护数据库。
7. **完成小程序备案及隐私配置。** 按公众平台提示填写备案、隐私保护指引以及实际使用的数据能力；实际需要的资料和步骤以账号后台为准。
8. **上传开发版本。** 开发者工具上传版本，例如 `1.0.0`，填写版本说明，在公众平台设置体验版，添加体验成员进行验收。
9. **提交审核。** 版本管理 → 开发版本 → 提交审核，填写功能页面、类目与说明；登录受限功能按平台要求提供审核可用方式，不能让审核员卡在没有权限的空页面。
10. **审核通过后发布。** 管理员在版本管理手动点击发布。扫码或搜索正式版本验收，确认新增、修改、跨端数据和权限都正常。

## 所需信息

本人微信小程序账号、AppID、真实主体与类目、选择的云开发环境或已备案后端域名、是否必须与网页共用同一数据库。无需在聊天里提供身份证、微信密码或 AppSecret。

## 迁移验收清单

- 菜品跨分类不重复，新分类可添加；原生数据库仍有并发去重保障。
- 页面完整显示食材、调料、方法、次数和评分。
- 微信身份与网页身份映射正确，不依赖访客提交的 owner_id。
- 两个合法客户端同时记录下厨不会丢次数；冲突编辑有提示。
- 旧网页导出的 JSON 能迁移，次数与评分保留。
- 真机下网络域名、授权、软键盘、返回导航、离线错误提示正常。
