## 环境与云函数

1. 环境名称建议 `jiajia-kitchen`；地域以控制台实际可选项和 Supabase 往返连接测试决定。将创建成功后的真实环境 ID 填入 `miniprogram/config.js`，不要填环境名称或 AppID。
2. 云函数名称固定为 `kitchen`，代码目录为 `cloudfunctions/kitchen`，入口 `index.main`。前端现有调用均使用该名称。
3. 当前依赖固定为 `@supabase/supabase-js@2.118.0` 和 `wx-server-sdk@3.0.4`，提供依赖锁文件。Supabase SDK 的 package.json 要求 Node.js >=22，不能使用控制台默认的 Node.js 20。官方文档列出的 `Nodejs22.21` 目前为公测，须确认当前微信环境实际提供该运行环境。如果不可选，应先调整并验证服务端依赖方案，再部署；不要忽略版本要求强行安装。
4. 准备的初始配置是 Nodejs22.21、256 MB 内存、20 秒超时、不配置定时触发器、不公开 HTTP 网关。使用 `cloudbaserc.example.json` 时从 `wechat/` 目录运行，填入真实环境 ID 后再部署。该文件仅是 CLI 配置示例，不会被微信开发者工具自动应用；使用工具部署时必须在云函数管理页面逐项核对配置。
5. 在开发者工具选择对应云环境，右键 `kitchen` → 上传并部署 → 云端安装依赖；核对依赖锁文件是否被采用。部署成功后先确认调用日志和真实返回值，再开展业务验证。依赖安装失败不能算部署完成。
6. 使用事件型云函数与 `wx.cloud.callFunction`。不新增公网入口，不将 Supabase service_role、数据库密码或微信 AppSecret 写入客户端或云函数。本项目只使用已有 publishable 公钥，用户 JWT 验证与数据库 RLS 继续决定数据访问权限。
